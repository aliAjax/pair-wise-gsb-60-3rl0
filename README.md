# 医疗器械上市后安全信号核查与处置平台

面向医疗器械上市后安全团队的本地工作台，用于合并投诉、维修、不良事件和现场报告，维护证据矩阵、调查任务、风险状态、结论版本和审计轨迹。

## 技术栈

- SvelteKit 2 + Vite + TypeScript
- Skeleton UI + Tailwind CSS
- Svelte stores
- SvelteKit Form Actions
- TanStack Query for Svelte
- Zod

## 主要工作区

- `/`：开放信号、高风险信号、任务和逾期总览
- `/signals`：关键词与多条件筛选、人工登记新信号
- `/signals/[id]`：证据矩阵、双人复核（待签复核单/双签/退回/复核单历史）、调查任务、结论版本、重新打开和审计
- `/trends`：发生率趋势与阈值核对
- `/batches`：批号覆盖与报告追踪
- `/audit`：跨信号审计时间线和 JSON 报告导出

## 高严重度信号的双人复核

高及以上风险（high/critical）信号进入**待处置**或**关闭**前，必须完成双人复核：

1. 处置人选择结论版本发起复核，系统生成**待签复核单**并锁定依据快照（结论版本、关联批号、未完成调查任务、证据/版本指纹），处置人当场签署，信号进入“复核中”。
2. 独立复核人账号须与处置人不同；逐项勾选确认结论版本、关联批号、未完成调查任务后才能签署。关闭复核还要求调查任务全部完成。
3. 证据或结论版本发生变化时，待签或已完成（待处置阶段）的复核单自动失效并退回复核，须重新走完整双签。
4. 已关闭记录全程只读、保持可读；新事件须“重新打开”，关闭签署同步失效。
5. 两个窗口同时签署时，通过跨标签页互斥锁 + 复核单 `revision` 乐观锁保证：先到一方生效，后到一方收到冲突提示，失败重签不会产生第二份有效签署。
6. 复核人可登记/更换，更换与退回均写入审计记录。

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18460`。

## 构建与检查

```bash
npm run check
npm run build
npm test        # 双人复核规则与跨窗口并发的 17 项 node:test 测试
```

无后端服务，页面使用确定性模拟数据，并将信号、证据、版本、复核单和审计记录持久化到浏览器 `localStorage`。关键表单先经过 SvelteKit Form Action 与 Zod 校验，再写入本地 store。
